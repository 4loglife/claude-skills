# 작성용 양식

체크리스트에서 ❌가 나온 항목을 고칠 때 그대로 복사해 쓴다. 출처 강의를 괄호에 적었다.

## 진입 파일 AGENTS.md / CLAUDE.md (4강)

```markdown
# AGENTS.md

## 프로젝트 개요
<한 문장: 무엇을, 누구를 위해>

## 빠른 시작
- 시작: `<명령>`
- 검증(완료 표시 전 필수): `<명령>`

## 하드 제약
- <협상 불가 규칙 3~7개>
- 검증 없이 기능을 완료로 표시하지 않는다
- 세션 끝에 클린 상태를 남긴다

## 주제 문서
- 아키텍처: docs/ARCHITECTURE.md
- 제품: docs/PRODUCT.md
- 진행 상황: PROGRESS.md
- 기능 목록: feature_list.json
```

## 진행 기록 PROGRESS.md (5강)

```markdown
# 프로젝트 진행 상황
## 현재 상태
## 완료된 항목
## 진행 중
## 알려진 이슈
## 다음 단계
```

## 세션 핸드오프 (5강)

```markdown
## 완료된 항목
- 

## 깨지거나 미검증된 항목
- 

## 다음으로 가장 좋은 단계
- 
```

## 다음 작업 (7강)

```markdown
- 현재 가장 높은 우선순위의 기능:
- 이 기능이 다음에 오는 이유:
- 통과로 간주되는 조건:
- 이 단계에서 변경해서는 안 되는 것:
```

## 기능 목록 항목 (8강) — 동작 + 검증 명령 + 상태

```json
{
  "id": "import-md",
  "behavior": "사용자가 .md 파일을 가져오면 문서 목록에 나타난다",
  "verify": "npm run test:e2e -- import-md",
  "passes": false
}
```

규칙: 한 번에 하나만 active · `passes`는 검증 스크립트만 바꾼다 · 한 세션에 끝낼 크기.

## 완료의 정의 (9강)

```markdown
## 완료의 정의
- 기능 완료 = 엔드투엔드 검증 통과, "코드가 작성됨"이 아님
- 1. 단위 테스트 → 2. 통합 테스트 → 3. 엔드투엔드 흐름
- 앞 단계가 실패하면 다음 단계로 가지 않는다
```

## 세션 종료 체크 (12강) — CLAUDE.md에 넣기

```markdown
## 세션 종료 체크리스트
- [ ] 빌드 통과
- [ ] 모든 테스트 통과
- [ ] 기능 목록·진행 기록 업데이트
- [ ] 디버그 코드 없음 (console.log, debugger, 임시 TODO)
- [ ] 표준 시작 경로 작동
```

## 스프린트 계약 (11강)

```markdown
스프린트 목표:
- 

완료 기준 (사용자 관점, 순서대로):
- 사용자가 ...
- 앱이 ...
- ...이 표시된다
```

## 평가 루브릭 (11강) — 차원별 1~5점

```markdown
- 근거: 답변이 출처에 명확히 연결되는가?
- 인용 품질: 출처 참조가 보이고 구체적인가?
- 기능성: 사용자가 흐름을 끝까지 완료할 수 있는가?
- 제품 일관성: 워크플로가 하나로 통합된 느낌인가?
```

## 리뷰 피드백 → 규칙 승격 (10강)

```markdown
반복되는 리뷰 코멘트:
> <예: 렌더러에서 fs를 직접 부르지 말고 preload 브릿지를 써라>

승격된 하네스 규칙:
- <린트/임포트 규칙 추가>
- <위반 시 출력할 "고치는 법" 메시지>
```

```markdown

### Round N

- 검증 결과: ✅ / ❌ / ⚠️
- 발견된 문제:
- 다음 라운드 계획:
- 사람 개입 필요: 예 / 아니오

## 차단 요인 목록
## 최종 결과
```

